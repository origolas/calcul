# ДЗ 3. TCP-клиент и сервер «Калькулятор»

## 1. Цель

Реализовать TCP-клиент и сервер с явными границами сообщений. Обеспечить передачу нескольких отдельных запросов в одном соединении, проверку ошибок и чтение полного ответа при частичных `recv()`.

## 2. Формат сообщений

Адрес сервера: `127.0.0.1:9000`. Используется TCP. Каждое сообщение состоит из четырёхбайтного префикса длины в big-endian и полезной части в UTF-8. Максимальная длина полезной части — 65536 байт.

| Направление | Содержимое | Пример |
|---|---|---|
| Клиент → сервер | Арифметическое выражение | `12+30*2` |
| Сервер → клиент | `OK:` и результат | `OK:72` |
| Сервер → клиент | `ERR:` и описание ошибки | `ERR:division by zero` |

Байты запроса `12+30*2`: `00 00 00 07 31 32 2B 33 30 2A 32`.

Байты ответа `OK:72`: `00 00 00 05 4F 4B 3A 37 32`.

Клиент читает сначала 4 байта длины, потом ровно указанное количество байт. Таким образом, два запроса подряд не объединяются в один. Поддерживаются `+`, `-`, `*`, `/`, скобки, пробелы и обычные десятичные числа.

## 3. Исходники

Программа сервера находится в `server.c`, программа клиента — в `client.c`. Исходный код не содержит комментариев.

Сервер: `socket() → bind() → listen() → accept() → recv() → send()`. Клиент: `socket() → connect() → send() → recv() → close()`. Оба обрабатывают частичную передачу и `EINTR`. Для отправки на Linux используется `MSG_NOSIGNAL`, чтобы разрыв соединения не завершал процесс сигналом `SIGPIPE`.

## 4. Сборка и запуск

```bash
cc -std=c11 -Wall -Wextra -Wpedantic -o server server.c -lm
cc -std=c11 -Wall -Wextra -Wpedantic -o client client.c
./server
```

В другом терминале:

```bash
./client '12+30*2' '(10-3)*4' '10/0' '5+bad'
```

## 5. Результаты практической проверки

Программа была скомпилирована с `-Werror` без предупреждений. Во время теста один клиент отправлял четыре запроса по одному TCP-соединению.

```text
12+30*2 -> OK:72
(10-3)*4 -> OK:28
10/0 -> ERR:division by zero
5+bad -> ERR:invalid expression
```

Проверен длинный запрос из 1000 единиц, разделённых знаком `+`: результат `OK:1000`. Проверен также запрос, отправленный вручную как фрейм с префиксом длины; сервер возвратил `ERR:invalid expression`.

Если сервер не запущен, клиент корректно завершается с кодом `1`:

```text
connect: Connection refused
```

При `recv() == 0` клиент сообщает о закрытии соединения без полного ответа; при `EINTR` операции чтения и записи повторяются.

## 6. Схема рукопожатия

```text
Клиент                                   Сервер
  |                                        |
  | -------- SYN, seq=x ----------------> |
  |                                        |
  | <--- SYN-ACK, seq=y, ack=x+1 -------- |
  |                                        |
  | -------- ACK, ack=y+1 --------------> |
  |                                        |
  |        connect() завершён             |
  |                                        |
  | -------- запрос 1 ------------------> |
  | <------- ответ 1 -------------------- |
  | -------- запрос 2 ------------------> |
  | <------- ответ 2 -------------------- |
  |                                        |
```

После третьего пакета клиентский `connect()` возвращает `0`. Значения `x` и `y` условные; реальные последовательные номера TCP нужно взять из записи трафика. Запросы 1 и 2 передаются в одном соединении без повторного SYN.

## 7. Проверка в Wireshark

Для локального теста используется интерфейс `lo` и фильтр `tcp.port == 9000`. В захвате должны быть видны TCP-рукопожатие, сегменты с полезными данными, подтверждения и завершение соединения. Запись реального трафика и скриншот Wireshark здесь не приложены; их необходимо получить на машине, где выполняется запуск.

## 8. Вывод

Реализован клиент-серверный калькулятор с префиксом длины. Сервер отделяет запросы и обрабатывает несколько сообщений в одном TCP-сеансе. Клиент читает ответ целиком, проверяет ошибки подключения и передачи данных. Протокол и команды воспроизведения приведены в `README.md`.
